# Technical Documentation - YouTube Deslopify

This document provides a technical overview of the YouTube Deslopify project codebase.

## Overview

The project aims to identify potentially low-quality ("slop") YouTube content watched by children by processing watch history, fetching video metadata, transcribing videos, and classifying the transcriptions using AI. It primarily uses Python scripts and relies on Google APIs (YouTube Data API, Gemini API) and a local SQLite database.

## Core Components

### 1. Database (`src/db_utils.py`)

-   Uses **SQLite** for local data storage (`data/youtube_deslopify.db`).
-   Manages database connection and initialization.
-   Defines the following tables:
    -   `channels`: Stores information about YouTube channels identified from watch history (name, URL, view count).
    -   `processed_videos`: Logs metadata for videos selected for processing (video ID, channel info, title, duration). Note: Videos are not downloaded locally.
    -   `audio_snippets`: Schema exists, but currently unused in scripts. Intended for storing paths to audio snippets if processing required separate audio files.
    -   `transcriptions`: Stores transcriptions generated by the Gemini API, including status, language, processing time, and any errors.
    -   `classifications`: Stores the results of the LLM-based classification of transcriptions, including scores for various criteria (language, coherence, education, engagement, appropriateness, overall), reasoning, and model used.

### 2. Authentication (`notebooks/00_setup_and_auth/`)

-   **Local (`00_youtube_oauth_local.py`):** Handles standard OAuth 2.0 flow using `client_secrets.json` and stores credentials in `token.json`. Requires manual interaction (copy/pasting URL). Run locally if needed.
-   **Databricks (`youtube_auth_and_fetch.py`):** Handles OAuth 2.0 flow within Databricks. Fetches client secrets (`youtube-client-id`, `youtube-client-secret`) from Azure Key Vault (`https://gattaca-keys.vault.azure.net/`). Stores the refresh token in a notebook-scoped variable (`saved_refresh_token`). It also includes logic to fetch the user's playlists.
-   **Playlist Fetch (`01_youtube_playlist_fetch.py`):** A separate Databricks notebook script designed to run after the main Databricks auth notebook (`%run ./youtube_auth_and_fetch`), using the stored `youtube_credentials` to fetch playlists.

### 3. Ingestion (`notebooks/01_ingestion/`)

-   **Channel Ingestion (`00_youtube_ingestion.py`):**
    -   Reads `*.json` files from `./data/watch_history/`.
    -   Parses entries to count views per channel URL.
    -   Extracts channel names associated with URLs (best effort).
    -   Inserts/updates the top N channels (default: 50) into the `channels` table in the SQLite DB.
-   **Video Metadata Fetching (`01_youtube_video_download.py`):**
    -   Reads channel URLs from the `channels` table.
    -   Uses the YouTube Data API to fetch recent video uploads for each channel.
    -   Filters videos based on duration (default: 60s - 3600s) to exclude shorts and very long videos.
    -   Scans up to a configured limit of videos per channel (default: 100) to find a target number of suitable videos (default: 3).
    -   Checks against the `processed_videos` table to avoid duplicates.
    -   Inserts metadata (ID, title, duration, channel info) for new, suitable videos into the `processed_videos` table. **Does not download video/audio files.**

### 4. Transcription (`notebooks/02_transcription/`)

-   **Gemini Transcription (`00_gemini_transcription.py`):**
    -   Reads video IDs from `processed_videos` that haven't been successfully transcribed (`status != 'success'` in `transcriptions` table or no entry).
    -   Uses the Gemini API (`gemini-2.5-flash-preview-04-17`) asynchronously to transcribe videos directly via their YouTube URLs (`https://www.youtube.com/watch?v={video_id}`).
    -   The prompt requests only the transcribed text.
    -   Includes specific safety settings (`HarmBlockThreshold.BLOCK_NONE`) to minimize content blocking by the API.
    -   Updates the `transcriptions` table with the text, status (`success`, `error`, `rate_limit`), processing time, and error messages.
    -   Uses `asyncio` with a semaphore (`MAX_CONCURRENT_TASKS`) for concurrent API calls.
    -   Handles rate limit errors (`429`) detected from the API.

### 5. Classification (`notebooks/03_classification/`)

-   **LLM Classification (`00_llm_classification.py`):**
    -   Reads successful transcriptions (`status = 'success'` and text not empty) from the `transcriptions` table that haven't been successfully classified.
    -   Uses the Gemini API (`gemini-2.5-flash-preview-04-17`) asynchronously to classify the transcription text based on a detailed prompt.
    -   The prompt asks the model to evaluate:
        -   Primary language (English, Czech, Dutch only - score 0 or 1)
        -   Coherence (1-5)
        -   Educational Value (1-5)
        -   Engagement Quality (Narrative vs. Sensory Overload) (1-5)
        -   Content Appropriateness (Avoiding low-value themes) (1-5)
        -   Overall Quality (1-5)
    -   Requires the output in a specific JSON format.
    -   Parses the JSON response from the model.
    -   Updates the `classifications` table with the scores, reasoning, model used, status, processing time, and errors.
    -   Uses `asyncio` with a semaphore for concurrency.
    -   Handles rate limits and parsing errors.

### 6. Library Enhancer (`src/library_enhancer.py`)

-   **Purpose:** Expands the list of potential high-quality channels by finding channels similar to those already identified as good.
-   **Trigger:** Designed to be run after the classification stage (`00_llm_classification.py`).
-   **Process:**
    -   Selects "seed" channels from the database where `classifications.overall_score >= 4`.
    -   Limits the number of seeds processed per run based on `MAX_REQUESTS_PER_RUN` (default: 20) to control API costs.
    -   For each selected seed channel, it calls the Perplexity Deep Research API (`sonar-deep-research`) using `src/perplexity_client.py` to find similar educational channels.
    -   The raw text output from Perplexity is then processed by the Gemini Flash API (`gemini-1.5-flash-latest`) using `src/llm_utils.py` to extract a structured list of channel names and URLs.
    -   These newly discovered channels are inserted into the `channels` table (`views` set to 0), avoiding duplicates based on URL (`ON CONFLICT DO NOTHING`).
-   **Dependencies:** Uses `src/db_utils.py`, `src/perplexity_client.py`, `src/llm_utils.py`.
-   **Concurrency:** Uses `asyncio` with a semaphore (`MAX_CONCURRENT_API_CALLS`) to manage concurrent calls to both Perplexity and Gemini APIs.

### 7. Approval Workflow (`notebooks/04_approval_workflow/`)

-   `00_parent_approval.py`: Currently an empty script. Intended for future development of a workflow for parental review/approval.

## Configuration

-   **API Keys:**
    -   Gemini API Key: Set via `GEMINI_API_KEY` environment variable (loaded from `.env`).
    -   Perplexity API Key: Set via `PERPLEXITY_API_KEY` environment variable (loaded from `.env`).
-   **OAuth:**
    -   Local: Requires `client_secrets.json` in `notebooks/00_setup_and_auth/`.
    -   Databricks: Requires Azure Key Vault secrets (`youtube-client-id`, `youtube-client-secret`) accessible via `DefaultAzureCredential`.
-   **Database:** Path configured in `src/db_utils.py` (defaults to `data/youtube_deslopify.db`).
-   **Watch History:** Expected in `data/watch_history/` as JSON files.
-   **Script Parameters:** Various constants (e.g., `TOP_N_CHANNELS`, `MAX_VIDEOS_PER_CHANNEL`, API model names, concurrency limits, `MAX_REQUESTS_PER_RUN`) are defined near the top of each script.

## Execution Flow

1.  **Setup:**
    -   Run `notebooks/00_setup_and_auth/00_youtube_oauth_local.py` once locally to get `token.json`, OR configure Azure Key Vault and run the auth part of `notebooks/00_setup_and_auth/youtube_auth_and_fetch.py` in Databricks.
    -   Place watch history JSONs in `data/watch_history/`.
    -   Ensure `.env` file exists with `GEMINI_API_KEY`.
    -   Run `pip install -r requirements.txt`.
2.  **Initialize DB:** The first script run (`00_youtube_ingestion.py`) will call `initialize_database()`.
3.  **Ingest Channels:** Run `notebooks/01_ingestion/00_youtube_ingestion.py`.
4.  **Fetch Video Metadata:** Run `notebooks/01_ingestion/01_youtube_video_download.py`.
5.  **Transcribe Videos:** Run `notebooks/02_transcription/00_gemini_transcription.py`.
6.  **Classify Transcriptions:** Run `notebooks/03_classification/00_llm_classification.py`.
7.  **(Optional) Enhance Library:** Run `src/library_enhancer.py` to discover similar high-quality channels based on classification results.
8.  **Repeat Metadata/Transcription/Classification:** If the enhancer added new channels, re-run steps 4, 5, and 6 to process videos from these new channels.

Scripts are generally designed to be run sequentially and are somewhat idempotent (e.g., they check for existing data before processing).
